# Глобальный баннер уведомлений со свайпом

**Дата:** 2026-06-02
**Проект:** CleanCity (Чистый Город), мобильное приложение KMP

## Проблема

In-app баннер новых уведомлений показывается только пока активен `MainShellScreen`
(вкладки). Подписка на `bus.newAnnouncements` и `SnackbarHost` живут внутри
`Scaffold` этого экрана. Как только поверх открывается отдельный экран (деталь
жалобы и т.п.), `MainShellScreen` выходит из композиции вместе с подпиской —
баннер не появляется. Свайпа для закрытия нет вообще: Snackbar висит ~10 сек
(`SnackbarDuration.Long`) и сам исчезает, либо закрывается кнопкой «Посмотреть».

## Цель

1. Баннер показывается на **любом экране авторизованной части** приложения
   (все вкладки + любые экраны, открытые поверх: деталь жалобы, настройки и т.д.).
2. Баннер можно **смахнуть вниз** для ручного закрытия.
3. Автоскрытие по таймеру сохраняется как запасной вариант.

На Splash / Login / Verify Email баннер не показывается — уведомления имеют смысл
только для залогиненного пользователя.

## Решение

Поднимаем баннер с уровня `MainShellScreen` на уровень `App.kt` (поверх всего
`Navigator`) и заменяем стандартный Snackbar собственным компонентом со свайпом.

### Компоненты

#### 1. `BannerController` (новый, `domain/`, синглтон в Koin)

- Хранит `StateFlow<BannerData?>` — текущий показываемый баннер (или `null`).
- `BannerData = { title: String, notificationId: Long? }`.
- Методы `show(data)` / `dismiss()`.
- Показываем по одному баннеру за раз: новый вытесняет предыдущий. Для transient-
  баннера это нормально и проще, чем очередь.

#### 2. `App.kt` — хост оверлея

- Внутри `key(processSeed, sessionKey)` оборачиваем `Navigator` в `Box`.
- Подписка на `bus.newAnnouncements` живёт здесь, **под гейтом `authState`**
  (Guest / Authenticated). На Splash / Login / Verify баннер не показывается.
- Поверх контента — `AnnouncementInAppBanner` через `AnimatedVisibility`
  (slide-in / slide-out снизу), выровненный по `Alignment.BottomCenter`.
- **Отступ снизу (вариант A):** баннер получает нижний padding = высота нижней
  панели вкладок + системные insets, чтобы на экранах с вкладками висеть *над*
  панелью навигации, а не перекрывать её кнопки.
  - Высоту панели **нельзя** прокинуть через `CompositionLocal`: оверлей живёт в
    `App.kt` (родитель), а `MainShellScreen` — его потомок внутри `Navigator`;
    `CompositionLocal`, выставленный потомком, родителю не виден.
  - Поэтому используем общий стейт снизу вверх: `BannerController` (или отдельный
    маленький holder) держит `StateFlow<Dp>` высоты нижней панели. `MainShellScreen`
    при композиции выставляет фактическую высоту панели (через `onSizeChanged` /
    `DisposableEffect`), при уходе из композиции сбрасывает в `0.dp`. Оверлей в
    `App.kt` читает это значение и применяет как нижний отступ. На экранах без
    панели значение = `0.dp`.

#### 3. `AnnouncementInAppBanner` (правим существующий)

- Принимает `BannerData` + `onDismiss` + `onAction` вместо `SnackbarData`.
- Жест свайпа: `Modifier.pointerInput` с `detectVerticalDragGestures`. При сдвиге
  вниз больше порога вызываем `onDismiss()`; уход анимируется смещением `offset`
  вниз.
- Кнопка «Посмотреть» → `onAction()` → переключение на `NotificationsTab`
  (через тот же механизм, что и сейчас).

#### 4. Автоскрытие

- В `App.kt` `LaunchedEffect(bannerData)` с `delay(~8–10 сек)` →
  `controller.dismiss()`, если баннер всё ещё тот же. Свайп вниз отменяет таймер
  сразу (баннер уходит → state становится `null` → эффект перезапускается).

### Поток данных

```
UnreadCountStore.pollOnce()
  → bus.emit(notification)
    → подписка в App.kt (только если залогинен)
      → controller.show(BannerData(...))
        → оверлей виден
          → автоскрытие через таймер ИЛИ свайп вниз → controller.dismiss()
          → тап «Посмотреть» → NotificationsTab + dismiss()
```

### Что убираем

Подписку `bus.newAnnouncements` и обвязку `SnackbarHost` из `MainShellScreen`
(текущие строки ~71–96). Логика переключения на `NotificationsTab` по тапу
сохраняется, но переезжает в обработчик `onAction` баннера.

### Что НЕ трогаем

Системная шторка (`AnnouncementBusBridge`, `NotificationTapBus`) — это отдельный
канал доставки уведомлений, он не меняется. Поллинг (`UnreadCountStore`, 30 сек)
и `NotificationEventBus` остаются как есть.

## Тестирование

- **Unit на `BannerController`:** `show` → state не `null`; `dismiss` → `null`;
  повторный `show` вытесняет предыдущий.
- **Ручной smoke на Samsung A33** (жесты и композиция надёжно проверяются только
  на устройстве):
  - баннер появляется на ленте;
  - баннер появляется на экране деталей жалобы;
  - баннер появляется на других вкладках;
  - свайп вниз закрывает баннер;
  - автоскрытие срабатывает, если не трогать;
  - тап «Посмотреть» открывает вкладку уведомлений и закрывает баннер;
  - на экранах с вкладками баннер висит над панелью навигации, не перекрывая её.

## Затронутые файлы

- `composeApp/.../domain/BannerController.kt` — **новый**.
- `composeApp/.../di/AppModule.kt` — регистрация `BannerController` в Koin.
- `composeApp/.../App.kt` — хост оверлея, подписка с гейтом по `authState`,
  таймер автоскрытия, чтение `StateFlow<Dp>` высоты нижней панели.
- `composeApp/.../ui/feature/shell/AnnouncementInAppBanner.kt` — новый API
  (`BannerData` + колбэки), жест свайпа вниз.
- `composeApp/.../ui/feature/shell/MainShellScreen.kt` — убрать подписку и
  `SnackbarHost`; публиковать высоту нижней панели в общий `StateFlow<Dp>`.
