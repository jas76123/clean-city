# Раскрытие временно скрытых блоков web-admin

Дата: 2026-07-09
Репозиторий: `cleancity-kmp`
Ветка: `main`

## Задача

В админ-панели `web-admin` четыре группы функциональности скрыты закомментированным кодом с маркером `HIDDEN_TEMPORARY`. Их нужно вернуть в интерфейс.

Скрытие было продуктовым решением под презентацию для администрации — чтобы не перегружать экран. Код всех скрытых блоков рабочий: в комментариях зафиксировано «секция готова», «компонент готов и протестирован». Презентация прошла, решение больше не актуально.

## Что скрыто

| Файл | Скрытый блок |
| --- | --- |
| `src/App.tsx`, `src/components/layout/navItems.ts` | Раздел «Аналитика» целиком — убран из меню и из роутинга, страница физически недостижима |
| `src/pages/AnalyticsPage.tsx` | Карточка `ReopenRateCard`, секция «Динамика» (`TrendCard`), колонка p90 в таблице категорий, секция «Влияние голосов» (`VotesImpactCard`), а также хуки `useReopenQuery`, `useTrendsRangeQuery`, `useVotesImpactQuery` и функция `groupByForPeriod` |
| `src/pages/analytics/MedianP90Card.tsx` | Показ p90 внутри карточки |
| `src/pages/SettingsPage.tsx` | «Журнал событий» (`AuditLogSection`) и «Экспорт PDF» (`ExportSection`) |

Всего 19 маркеров `HIDDEN_TEMPORARY` в четырёх файлах плюс закомментированные секции в `SettingsPage.tsx`.

## Установленные факты

Ничего из скрытого не сгнило за время простоя:

- Бэкенд-эндпоинты живы: `/reopen`, `/trends`, `/votes-impact`, `/export/monthly-report.pdf` в `AnalyticsRoutes.kt`, `/admin/audit-log` в `AuthRoutes.kt`.
- Все хуки присутствуют в `hooks/dashboardQueries.ts`.
- Все компоненты и их собственные тесты на месте: `ReopenRateCard.tsx`, `TrendCard.tsx` + `TrendCard.test.tsx`, `VotesImpactCard.tsx` + `VotesImpactCard.test.tsx`, `AuditLogSection.tsx`, `ExportSection.tsx` + `ExportSection.test.tsx`.

Блоки уже открывали однажды (`f312206`) и затем скрыли снова (`41c9ba2`). Коммит `41c9ba2` добавил все 19 маркеров, закомментировал секции в «Настройках» и перевернул утверждение в `SettingsPage.test.tsx`. С момента `41c9ba2` ни один из шести затронутых им файлов не менялся, и его реверс накладывается без конфликтов (проверено).

## Решение

Отреверсить `41c9ba2` и сверху удалить осиротевший компонент-заглушку.

Реверс выбран вместо ручного раскомментирования потому, что он побайтово восстанавливает состояние, которое уже существовало и проходило тесты, снимает все 19 маркеров разом и не оставляет шанса пропустить один из блоков. Ручная правка 19 мест в шести файлах такой гарантии не даёт: о закомментированном коде компилятор не предупреждает.

Изменение оформляется одним коммитом с осмысленным сообщением, а не автоматическим «Revert ...»:

```
git revert --no-commit 41c9ba2
git rm web-admin/src/pages/placeholders/SectionPlaceholder.tsx
git commit
```

### Уборка мёртвого кода

`src/pages/placeholders/SectionPlaceholder.tsx` — компонент-заглушка «Раздел в разработке», оставшийся от эпохи скрытия. Не импортируется нигде. Удаляется.

Хуки `useTrendsQuery` и `useSlaQuery` в `dashboardQueries.ts` также не используются нигде, но они не связаны со скрытием и существовали неиспользуемыми до него. В рамках этой задачи не трогаем.

## Тесты

Реверс сам чинит `SettingsPage.test.tsx`: утверждение возвращается с «журнал скрыт» на «журнал виден».

`AnalyticsPage.test.tsx` править не нужно. Его проверка «не отрисовывает кнопку Экспорт PDF» относится к странице аналитики, а экспорт живёт в разделе «Настройки», поэтому утверждение остаётся верным и после раскрытия.

## Проверка

1. `npm run test` в `web-admin` — vitest. Ожидаем, что пройдут в том числе тесты `TrendCard` и `VotesImpactCard`, которые до сих пор покрывали неиспользуемые компоненты.
2. `npm run build` — `tsc -b` ловит несуществующие импорты и рассогласование типов. Точка внимания: `p90ResolutionHours` в типе категории объявлен опциональным (`?: number | null`), и возвращаемая колонка p90 должна с этим согласоваться.
3. `npm run dev` и ручной осмотр: раздел «Аналитика» появился в меню и открывается; в нём видны ReopenRateCard, «Динамика», колонка p90, «Влияние голосов»; в «Настройках» видны «Журнал событий» и «Экспорт PDF», кнопка экспорта отдаёт PDF.

## Риски

`TrendCard` и «Влияние голосов» — единственные блоки, которым нужен исторический ряд, а не текущий срез. На базе без накопленной истории они отрисуются пустыми. Это обнаруживается на шаге 3 проверки. Для наполнения демонстрационными данными существует `ops/seed-analytics-demo.sh`.

Остальные блоки зависят только от текущего состояния данных и пустыми быть не могут.

## Выкатка

`web-admin/dist` не хранится в git (см. `web-admin/.gitignore`); панель собирается образом `deploy/web-admin.Dockerfile`. После коммита нужна пересборка образа и `up -d` через `deploy/docker-compose.prod.yml`.

Обязательно: `APP_STAGE=PROD`, чтобы dev-seed не залил фиктивные данные. Никогда не `down -v`.
