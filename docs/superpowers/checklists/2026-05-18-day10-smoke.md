Если уже есть — пропускаем.

## Smoke #7 (cluster tap) — на реальном устройстве

Это отдельная задача, не на AVD. Требует физический Android-телефон.

### Подготовка APK для реального устройства

Текущий APK ходит на `10.0.2.2:8081` — это работает только в AVD. Два варианта:

**A. `adb reverse` + пересборка с `localhost`** (рекомендую):

```bash
# 1. Подменить URL в local.properties
sed -i '' 's|http://10.0.2.2:8081|http://localhost:8081|' ~/Desktop/Myapp/cleancity-kmp/local.properties

# 2. Пересобрать
cd ~/Desktop/Myapp/cleancity-kmp && ./gradlew :composeApp:assembleDebug

# 3. На телефоне: Настройки → О телефоне → 7 раз тап на «Номер сборки» → включить
#    Настройки → Для разработчиков → Отладка по USB ON. Подключить кабелем, разрешить отладку.

# 4. Прокинуть порт хоста на телефон
adb reverse tcp:8081 tcp:8081

# 5. Установить
adb install -r ~/Desktop/Myapp/cleancity-kmp/composeApp/build/outputs/apk/debug/composeApp-debug.apk

# 6. После теста — откатить URL обратно для AVD
sed -i '' 's|http://localhost:8081|http://10.0.2.2:8081|' ~/Desktop/Myapp/cleancity-kmp/local.properties
```

**B. Прописать IP MacBook в локальной сети** (если телефон в той же Wi-Fi):

```bash
# узнать IP Mac
ipconfig getifaddr en0
# например 192.168.1.42 — подставить в local.properties:
# API_BASE_URL=http://192.168.1.42:8081
# пересобрать и установить как в варианте A шаги 2, 3, 5
```

## Найденные баги

### 🔴 BUG-1: MarkerPreview→Detail и в целом маркер-тап на AVD не работают (расширение Day 9 #7)

- **Сценарий:** #11
- **Шаги:** На карте тап на любой маркер (одиночный pin или кластер) — 8 разных координат пробовала
- **Ожидаемо:** появляется MarkerPreviewSheet с кнопкой «Открыть детально», либо камера зумит к кластеру
- **Фактически:** ничего не происходит, UI hierarchy не меняется
- **Причина (гипотеза):** Yandex MapKit рендерит карту в `SurfaceView` внутри `ViewFactoryHolder` Compose-обёртки. Touch events до `MapObjectTapListener` / `ClusterTapListener` не доходят на AVD.
- **Расширение Day 9 #7:** ранее задокументирован только `ClusterTapListener`; сейчас видно, что и одиночные маркеры (через `MapObjectTapListener`) тоже не реагируют
- **Что нужно:** проверить на реальном Android-устройстве (то же что и пункт #3 — smoke #7). Если на реале маркеры тоже молчат — workaround через `MapInputListener` + геометрический hit-test, или через RawMap touch dispatch
- **Unit-тесты:** Логика `MarkerPreviewSheet` → `navigator.push(ComplaintDetailScreen(id))` корректна (компилируется, путь от `MapMarker.id: Long` к `ComplaintDetailScreen(complaintId: Long)` верный). Это исключительно проблема Yandex SDK + Compose + AVD.
