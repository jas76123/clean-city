# Day 17D — PDF «Сводный отчёт за месяц»

**Статус:** дизайн утверждён 2026-05-28
**Связано:** `docs/PLAN.md` § День 17 (строки 443–446), `docs/SPEC.md` § 5.5 / § 12.7
**Следующий шаг:** имплементационный план через writing-plans

## 1. Цель

Дать админу CleanCity возможность одним кликом скачать готовый PDF-отчёт за предыдущий полный календарный месяц для передачи в администрацию города Сочи. Это последний открытый кусок Дня 17; после него весь Day 17 закрыт.

Заведомо вне MVP (по SPEC § 12.7): отчёты «Реестр жалоб», «Отчёт по SLA», «Голосование жителей» — UI-карточки остаются disabled со статусом «Скоро».

## 2. Скоуп

**Включено:**
- Новый бэкенд-эндпоинт `GET /analytics/export/monthly-report.pdf`.
- Новые методы в `AnalyticsService` для произвольного `[from, to)` диапазона.
- Серверная генерация PDF через OpenPDF 1.3.30.
- Кириллический шрифт DejaVuSans (Regular + Bold) в `backend/src/main/resources/fonts/`.
- Новый компонент `ExportSection` в web-админке, монтируется в `SettingsPage`.
- Тесты: unit (PDF-сервис, range-методы), integration (route + auth), фронт (ExportSection).

**Исключено:**
- Графики, диаграммы, картинки в PDF.
- Логотип в шапке PDF.
- Выбор произвольного месяца через UI или query-параметр.
- Реализация других трёх отчётов (Реестр / SLA / Голосование) — disabled-карточки без логики.
- Кэширование сгенерированных PDF.
- Email-рассылка отчётов.
- Локализация на другие языки.

### 3.1 Бэкенд

    └── MonthlyReportLayout.kt       — OpenPDF-вёрстка (только верстка, ни одного запроса к БД)

**Разделение `MonthlyReportPdfService` ↔ `MonthlyReportLayout`:**
- `Service` отвечает за «какой месяц», «откуда брать данные», возвращает `ByteArray`.
- `Layout` принимает уже готовые DTO и пишет в `OutputStream`. Чистый рендер, никаких знаний о БД.
- Это позволяет тестировать сервис на моках и layout — на статических данных.

**DI:** `MonthlyReportPdfService` инжектится в `AnalyticsRoutes` через тот же паттерн, что и существующий `AnalyticsService` (регистрация в `Application.kt` в analytics-блоке).

## 4. Эндпоинт

```
GET /analytics/export/monthly-report.pdf
```

**Авторизация:** `ADMIN_ROLES = setOf(ADMIN, OPERATOR)` — переиспользуем существующий `requireAdmin()` гард из `AnalyticsRoutes.kt:17,83`. RESIDENT → 403. Без токена → 401.

**Query-параметры:** отсутствуют. Период всегда «предыдущий полный календарный месяц» по таймзону `Europe/Moscow`. Вычисляется на сервере на момент запроса.

**Расчёт периода:**
- `now = ZonedDateTime.now(ZoneId.of("Europe/Moscow"))`
- `monthEnd = now.toLocalDate().withDayOfMonth(1).atStartOfDay(MSK)` — начало текущего месяца MSK
- `monthStart = monthEnd.minusMonths(1)` — начало прошлого месяца MSK
- Период = `[monthStart, monthEnd)` (полузакрытый интервал).
- Пример: 28.05.2026 → отчёт за `[2026-04-01 00:00 MSK, 2026-05-01 00:00 MSK)`.
- Граничный случай 1-го числа: `01.06.2026 00:30 MSK` → отчёт всё равно за май.

**Ответ 200 OK:**
```
Content-Type: application/pdf
Content-Length: <bytes>
Content-Disposition: attachment; filename="cleancity-monthly-report-2026-04.pdf"
```

Имя файла — ASCII (`cleancity-monthly-report-{YYYY}-{MM}.pdf`). Это сознательное упрощение, чтобы не дурить с `filename*=UTF-8''…` (RFC 6266) и не получить кракозябры в Windows. Русский заголовок присутствует **в шапке самого PDF**.

**Тело ответа:** байты PDF, сгенерированные в `ByteArrayOutputStream`. Для месячных объёмов размер 20–80 KB, стриминг не нужен.

**Ошибки:**
- `401 Unauthorized` — нет/невалидный JWT.
- `403 Forbidden` — роль не в `ADMIN_ROLES`.
- `500 Internal Server Error` — ошибка генерации (нет шрифта, OOM, баг в layout). Обрабатывается общим `ExceptionHandler` → JSON `{error: "PDF generation failed"}`.

**Edge case «нет данных».** Если за прошлый месяц нет ни одной жалобы — PDF всё равно генерируется (HTTP 200), все KPI = 0, таблицы районов содержат 4 строки с нулями, таблица SLA пуста с подписью «За отчётный период данных нет.» Это важно для пилотного запуска: первые недели после деплоя отчёт может быть пустым.

**Кэширование:** не используется. Заголовков `Cache-Control` для этого эндпоинта не выставляем (наследуется `no-store` от общего пайплайна Ktor). Генерация занимает миллисекунды, а ручная правка статусов задним числом сломала бы кэш.

## 5. Новые методы в `AnalyticsService`

Существующие методы `byDistrict(period: AnalyticsPeriod)` работают с rolling-периодами относительно `now()` и не подходят для «апрель 2026». Добавляем перегрузки с явным диапазоном:

```kotlin
fun overviewRange(from: OffsetDateTime, to: OffsetDateTime): OverviewResponse
fun byDistrictRange(from: OffsetDateTime, to: OffsetDateTime): List<DistrictRow>
fun slaRange(from: OffsetDateTime, to: OffsetDateTime): List<SlaRow>
```

**Реализация:** все три метода вызывают существующий `AnalyticsRepository.loadComplaints(periodStart = from)` и фильтруют результат по `createdAt < to` в памяти (как уже сделано в `strategicKpis(periodStart, periodEnd)` на строках 205–235). DTO-типы — те же, что используют существующие эндпоинты `/analytics/overview`, `/analytics/by-district`, `/analytics/sla`. Это даёт совместимость по форматам и нулевое дублирование.

**Граничные условия:**
- Жалоба с `createdAt == from` — попадает в результат.
- Жалоба с `createdAt == to` — НЕ попадает.

### 6.3 Правила содержимого

- **KPI-блок:** ровно 6 строк всегда (даже если все значения = 0). Подпись слева (10pt), значение справа (10pt bold).
- **SLA-баннер:** строка `⚠ Нарушено SLA: N жалоб` показывается только если `slaBreachCount > 0`. Цвет `#E8443C`. Если 0 — баннер не выводится, не оставляем пустую строку.
- **Таблица районов:** ровно 4 строки в фиксированном порядке (Центральный → Адлерский → Хостинский → Лазаревский), даже если в каком-то 0 жалоб.
- **SLA-таблица:** выводятся только те категории, у которых `count > 0` за период. Если за весь месяц нет ни одной resolved-жалобы в категории — поля «Среднее» и «Нарушено» показывают `—`. Если ни одной активной категории нет — вместо таблицы строка «За отчётный период данных нет.»
- **Footer:** «стр. X из Y» в правом нижнем углу через `HeaderFooter` OpenPDF.

### 6.4 Локализация

- Категории — на русском, через те же лейблы, что отдаёт `GET /categories`.
- Числа без разделителей тысяч (`142`, не `1 142` — если переваливаем за 1000, реализуем форматирование в plan-фазе через `String.format(Locale("ru"), "%,d", n)`).
- Часы: `48 ч`, `31 ч` (число + пробел + «ч»).
- Процент: `12%` (целое + знак).
- Месяц в шапке — родительный падеж: «за апрель», «за май», и так далее. Хардкод-таблица 12 строк в `MonthlyReportLayout`.

### 6.5 Стиль

Монохром (чёрный текст на белом). Единственное исключение — SLA-баннер (`#E8443C`). Это печатный отчёт «для мэрии», а не дашборд — не пытаемся повторить дизайн web-админки.

### 7.4 Скачивание

```ts
const res = await api.get('/analytics/export/monthly-report.pdf', {
  responseType: 'blob',
})
const filename = parseContentDisposition(res.headers['content-disposition'])
  ?? 'cleancity-monthly-report.pdf'
const url = URL.createObjectURL(res.data)
const a = document.createElement('a')
a.href = url
a.download = filename
a.click()
URL.revokeObjectURL(url)
```

- `responseType: 'blob'` обязателен — иначе axios попытается парсить бинарь как JSON и сломается.
- Имя файла парсится из `Content-Disposition`; fallback на статичное `cleancity-monthly-report.pdf` если хедер недоступен.
- Существующий axios-перехватчик (`src/api/`) обрабатывает 401/403 → редирект на login. Остальные коды обрабатываем локально через toast.

## 9. Решения и trade-offs

| Решение | Альтернатива | Почему так |
|---------|--------------|------------|
| OpenPDF 1.3.30 | Apache PDFBox / openhtmltopdf | Уже зафиксировано в PLAN/SPEC; высокоуровневый API (`PdfPTable`); минимум кода для 3 таблиц без графики; Apache 2.0 |
| Без графиков | Графики как PNG из data-URL | Решение юзера: только KPI + таблицы. Экономит работу с рендерингом chart.js → PNG |
| Период = предыдущий полный месяц | Текущий месяц / выбор через UI | Решение юзера: самый частый паттерн отчётности; нет UI-контролов; цифры стабильны |
| Имя файла ASCII | UTF-8 через `filename*=` | Совместимость со всеми браузерами и Windows-копированием |
| Без кэширования | LRU / file-cache | Генерация мс; правки статусов задним числом сломали бы кэш |
| 3 disabled-карточки | Скрыть их полностью | Зафиксировано в SPEC § 12.7; «полнота» интерфейса для защиты диплома |
| Один отчёт = одна вёрстка | Шаблонизация (Mustache/Pebble) | Один отчёт в MVP, шаблонизация — overkill |
| DejaVuSans (1.4 MB) | Системный шрифт / Arial Cyrillic | Гарантированная кириллица на любом контейнере без зависимости от ОС |

## 10. Риски

- **Размер шрифта в репо.** `DejaVuSans.ttf + Bold.ttf` суммарно ~1.4 MB. Добавятся в git history. Альтернативой могла бы быть подкачка из CDN при старте, но это новая внешняя зависимость. Решение — коммитим в `resources/fonts/`, проверяем `.gitattributes` на бинарность.
- **Дата генерации в тестах.** Тесты на текст PDF могут флакать, если в шаблоне меняется формат даты. Митигация: тестируем существование подстрок («Сводный отчёт за апрель 2026»), а не точное побайтовое совпадение.
- **«Категории без resolved».** Если в категории за месяц 0 resolved — `avgResolutionHours = null`. В таблице SLA рисуем `—`. В тесте проверяем оба случая (есть resolved / нет resolved).
