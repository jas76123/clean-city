# Day 18 — Деплой CleanCity на Yandex Cloud: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Развернуть боевой стенд `clean--city.ru` (mobile через хостинг APK + web-админка + backend) на одной VM в Yandex Cloud, с ежедневным GPG-бэкапом БД в Object Storage и healthcheck-алертами в Telegram.

**Architecture:** Одна VM Ubuntu 24.04 → `docker compose` (caddy + backend + web-admin + db) → 3 поддомена через REG.RU DNS → Let's Encrypt через Caddy. Фото жалоб в bucket `cleancity-photos-prod` (public-read GET, без листинга). Бэкапы в bucket `cleancity-backups` (private, write-only IAM-аккаунт, lifecycle 30 дней). Cron-инфра (`ops/install-cron.sh`) уже в репо.

**Tech Stack:** Ubuntu 24.04, Docker Compose v2, Caddy 2, Ktor backend (`STAGE=PROD`), nginx-alpine для статики React, Postgres+PostGIS 16, AWS CLI v2 для S3, gpg для шифрования бэкапов, qrencode для QR.

**Spec:** `docs/superpowers/specs/2026-05-28-day18-deploy-design.md`

## Task 0: Добавить блок `storage.s3` в `application.conf`

**Зачем:** `Application.kt` читает `storage.s3.bucket/access_key/secret_key/endpoint/public_url_base` через `environment.config.propertyOrNull(...)`, но в `application.conf` этих ключей нет — Ktor вернёт null, бэкенд молча уйдёт в `LocalStorageService` (см. ветку на 223-й строке Application.kt). Нужно добавить ключи с ENV-fallback, и заодно `EMAIL_FROM` (default `noreply@cleancity.local` нам не подходит).

**Files:**
- Modify: `backend/src/main/resources/application.conf`

- [ ] **Step 1: Прочитать текущий блок storage и email**

Run: `grep -A 5 "^storage\|^email" backend/src/main/resources/application.conf`
Expected: видим блок `storage { path = ... }` без s3, и `email { from = "noreply@cleancity.local" ... }`.

- [ ] **Step 2: Заменить блок storage**

В файле `backend/src/main/resources/application.conf` заменить:
```
storage {
    path = "./uploads"
    path = ${?STORAGE_PATH}
}
```
на:
```
storage {
    path = "./uploads"
    path = ${?STORAGE_PATH}
    s3 {
        bucket = ""
        bucket = ${?STORAGE_S3_BUCKET}
        access_key = ""
        access_key = ${?STORAGE_S3_ACCESS_KEY}
        secret_key = ""
        secret_key = ${?STORAGE_S3_SECRET_KEY}
        region = "ru-central1"
        region = ${?STORAGE_S3_REGION}
        endpoint = "https://storage.yandexcloud.net"
        endpoint = ${?STORAGE_S3_ENDPOINT}
        public_url_base = ""
        public_url_base = ${?STORAGE_S3_PUBLIC_URL_BASE}
    }
}
```

# deploy/web-admin.Dockerfile
# Двухстейджевый билд: node собирает SPA, nginx-alpine раздаёт статику.

FROM node:20-alpine AS build
WORKDIR /app
COPY web-admin/package.json web-admin/package-lock.json* ./
RUN npm ci
COPY web-admin/ ./
# API_BASE для прода захардкожен через VITE_-переменную при билде.
ENV VITE_API_BASE_URL=https://api.clean--city.ru
RUN npm run build

FROM nginx:alpine
COPY --from=build /app/dist /usr/share/nginx/html
# SPA-роутинг: всё, что не статика, → index.html.
RUN printf 'server {\n  listen 80;\n  root /usr/share/nginx/html;\n  index index.html;\n  location / {\n    try_files $uri $uri/ /index.html;\n  }\n}\n' > /etc/nginx/conf.d/default.conf
